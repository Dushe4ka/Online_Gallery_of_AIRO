## 1. Описание проекта

**Online Gallery of AIRO** — Telegram-бот для художественной галереи. Позволяет пользователям просматривать каталог картин, информацию о художнике, мероприятиях и контактах. Администраторы управляют контентом через админ-панель.

**Стек:** Python 3.10+, aiogram 3.x, SQLite (aiosqlite)

---

## 2. Требования

- **Python** 3.10 или выше
- **Токен Telegram-бота** (получить у [@BotFather](https://t.me/BotFather))
- **Telegram ID администратора** (можно узнать через [@userinfobot](https://t.me/userinfobot))

## 4. Установка и настройка

### 4.1 Клонирование и виртуальное окружение

```bash
cd Online_Gallery_of_AIRO
python3 -m venv myvenv
source myvenv/bin/activate   # Linux/macOS
# или: myvenv\Scripts\activate   # Windows
```

### 4.2 Установка зависимостей

```bash
pip install -r requirements.txt
```

Основные зависимости: `aiogram`, `aiosqlite`, `python-dotenv`, `schedule`.

### 4.3 Настройка переменных окружения

Создайте файл `.env` в корне проекта:

```env
BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
ADMIN_IDS=123456789,987654321
DB_PATH=bot_data.db
```

| Переменная | Описание | Обязательно |
|------------|----------|-------------|
| `BOT_TOKEN` | Токен от @BotFather | Да |
| `ADMIN_IDS` | ID админов через запятую | Да |
| `DB_PATH`  | Путь к БД (опционально, по умолчанию `bot_data.db` в коде) | Нет |

> **Важно:** Файл `database.py` использует путь `bot_data.db` напрямую. Переменная `DB_PATH` в `config.py` пока не подключена к `database.py`.

## 5. Запуск

### 5.1 Обычный запуск

```bash
python bot.py
```

Бот запускается в режиме long polling. В консоли должно появиться:
```
INFO:aiogram.dispatcher:Run polling for bot @YourBot ...
```

### 5.2 Запуск бэкапа отдельно (опционально)

```bash
python service.py
```

Отправляет бэкап БД админам по расписанию (понедельник 09:00). В основном режиме бэкап работает как фоновая задача внутри `bot.py`.

### 5.3 Продакшн (PM2, systemd и т.д.)

Пример для PM2:

```bash
pm2 start bot.py --name airo_bot --interpreter python3
pm2 save
pm2 startup
```

## 6. Архитектура

### 6.1 Точка входа

`bot.py` — единственная точка входа. В `main()`:
1. Инициализируется БД
2. Регистрируются обработчики команд и кнопок
3. Запускается фоновая задача бэкапа
4. Запускается `dp.start_polling(bot)`

### 6.2 Регистрация обработчиков

- `register_handlers()` — регистрирует `/start` и обработчики reply-кнопок разделов.
- Обработчики callback и FSM регистрируются декораторами `@dp.callback_query` и `@dp.message` при импорте модуля.

### 6.3 Модуль admin.py

`admin.py` импортирует `dp`, `sections`, `bot` из `bot.py` и регистрирует свои обработчики на том же диспетчере. Чтобы они работали, `admin.py` должен быть импортирован (например, `import admin` в `bot.py`). В текущей версии `bot.py` не импортирует `admin.py`, поэтому используется только логика админки из `bot.py`.

## 7. База данных

### 7.1 Файл

`bot_data.db` (SQLite, создаётся автоматически при первом запуске).

### 7.2 Таблицы

| Таблица | Описание |
|---------|----------|
| `users` | Подписчики (user_id) |
| `moderators` | Модераторы (user_id) |
| `about_artist`, `about_style`, `catalog`, `events`, `guests`, `cooperation`, `contacts` | Контент по разделам |
| `{section}_media` | Медиафайлы (content_id, media_type, file_id) |

### 7.3 Схема контента

Для каждого раздела:
- `{section}` — id, title, description, published_at
- `{section}_media` — id, content_id, media_type ('photo'|'video'), file_id

### 7.4 Основные функции (database.py)

| Функция | Описание |
|---------|----------|
| `init_db()` | Создаёт все таблицы |
| `get_content(section)` | Контент с медиа (JOIN) |
| `get_posts(section)` | Только посты (id, title) для пагинации |
| `add_content(section, title, description, media_files)` | Добавление контента |
| `delete_content(section, content_id)` | Удаление поста |
| `delete_all_content(section)` | Очистка раздела |
| `add_user`, `add_moderator`, `remove_moderator`, `is_moderator`, `get_moderators` | Работа с пользователями и модераторами |

## 9. Основные компоненты

### 9.1 Разделы (sections)

```python
sections = {
    "about_artist": "🖌 О художнике",
    "about_style": "🎨 О направлении",
    "catalog": "🖼 Каталог картин",
    "events": "📅 Мероприятия",
    "guests": "👥 Наши гости",
    "cooperation": "🤝 Сотрудничество",
    "contacts": "📞 Контакты"
}
```

### 9.2 Пользовательский сценарий

1. `/start` — регистрация, главное меню с reply-кнопками.
2. Нажатие кнопки раздела → `send_content()` — отправка постов (медиагруппы + текст).
3. Учёт лимитов: caption до 1024 символов, пауза 1 сек между постами, retry при Flood control.

### 9.3 Админ-панель

- Команда `/admin` (только для ID из ADMINS).
- Добавление контента (раздел → название → описание → фото/видео).
- Удаление контента (с пагинацией по 8 постов).
- Очистка раздела.
- Управление модераторами.

### 9.4 Особенности реализации

- **Пагинация:** при удалении контента — 8 постов на страницу, callback `delpg:{section}:{page}`.
- **Caption:** обрезка до 1024 символов, полный текст — отдельным сообщением.
- **Flood control:** `_send_with_retry()` + `asyncio.sleep()` между постами.
- **Бэкап:** `service.py` — ZIP базы, отправка админам по расписанию.
